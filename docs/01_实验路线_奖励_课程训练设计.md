# Bomberman：实验路线、奖励与课程训练设计

> 状态：设计基线与下一阶段计划（2026-08-25）
>
> 目的：让每个实验名称清楚说明“用什么 agent、用什么训练反馈、在什么任务上、按什么顺序训练”。
> 本文不改写任何既有结果；`A00` 与已经完成的 runs 始终保留为可复现实验基线。

## 1. 先用一套共同语言

一个 Bomberman 实验由四个彼此独立的维度组成：

```text
R：Route      = agent 如何表示状态、如何估值、如何学习
A：Reward     = 训练时什么事件得到什么反馈
C：Curriculum = 训练任务按什么顺序或比例出现
T：Task       = 一个具体场景与对手条件
```

这里的 `C` 是 **curriculum（课程训练）**，不是 `classic`。`classic` 是一种任务场景，归入 `T`。

例如：

```text
R01_A01_C00_T03
│   │   │   └─ 在 solo classic 上做单任务训练
│   │   └───── 不混合任务的固定课程
│   └───────── 使用“死亡有惩罚”的 A01 训练奖励
└───────────── 手工特征 + 线性 Q + Online Q-learning 路线
```

正式 JSON 和 run-id 可以保留简短、可读的文件名；完整的 R/A/C/T 定义必须写入 config snapshot、实验文档和结果报告。一个课程包含多个任务时，run-id 可写为 `..._c02_capability_ladder`，任务列表由该 C 编号的表格定义，避免文件名变得过长。

## 2. 第一性原理：为什么必须拆开这四个维度

强化学习不是从标准答案中学习，而是在交互中学习：

```text
状态 → 选动作 → 环境产生事件 → 训练 reward → 更新动作价值
```

如果 agent 从未看到“放炸弹后成功逃跑并继续得分”的结果，它就无法可靠地区分“危险地拿一枚币后死亡”和“安全地继续拿更多币”。因此：

- **R** 决定 agent 能否表达这种区别；
- **A** 决定环境是否把这种区别反馈给它；
- **C** 决定它能看到多少简单或困难的经验；
- **T** 决定经验本身包含什么地图、箱子、金币和对手。

若一次同时改 R、A、C 和 T，结果即使改善，也无法知道改善来自模型、reward 还是任务更容易。受控比较一次只改一个维度；确定有效的组合后，才做最终能力课程。

## 3. 任务目录：先 solo，后对抗

当前阶段的任务一律只有自己一个 agent。这样 `KILLED_OPPONENT` 不会发生，训练重点是存活、导航、炸箱与采币。

| Task ID | 官方 scenario | 箱子密度 / 金币数 | 对手 | 主要能力 | 状态 |
|---|---|---|---|---|---|
| `T01` | `coin-heaven` | 0 / 50 | 无 | 移动、导航、直接采集可见金币 | 已使用 |
| `T02` | `loot-crate` | 0.75 / 50 | 无 | 炸箱、逃生、回收大量隐藏金币 | 候选中间任务 |
| `T03` | `classic` | 0.75 / 9 | 无 | 稀疏条件下安全炸箱与采集 | 当前主任务 |
| `T04` | `classic` | 0.75 / 9 | 固定对手配置 | 对抗、击杀、生存与采集 | 以后才启动 |

金币生成规则尤其重要：环境会**优先把金币放在箱子下面**。因此：

- `T01` 没有箱子，50 枚币全部直接可捡；放炸弹对拿币没有必要；
- `T02`、`T03` 有大量箱子，金币通常先藏在箱子下；必须学习“炸箱 → 逃生 → 捡币”。

不同任务的原始 score 上限不同（`T01` 为 50，`T03` 为 9），所以只能在**同一任务**中比较 score，不能把 Coin Heaven 的 30 分和 Classic 的 1 分直接视为同等强度。

## 4. 路线目录：R 表示 agent 本身

| Route | 状态表示 | 模型 | 学习规则 | 目的 / 状态 |
|---|---|---|---|---|
| `R01` | `handcrafted_v1`，44 维 | 六 head 线性 Q | Online one-step Q-learning | 已完成、作为可解释 baseline |
| `R02` | 与 R01 相同 | `44 → 64 → 32 → 6` NumPy MLP | 与 R01 相同 | 已实现但当前暂停；用于单独测试模型容量 |
| `R03+` | 以后单独定义 | 未定 | 未定 | 不与当前 R01 reward/课程实验混合 |

### R01 固定内容

`R01` 的路线本身保持不变：44 维手工状态、线性六动作 Q、Online Q-learning、立即合法动作 mask、`alpha=0.02`、`gamma=0.95`、训练 `epsilon=0.15`、评估 `epsilon=0`。它不包含 replay、target network、SARSA、DQN、CNN 或第二层安全过滤。

换 reward 或换课程时，R01 仍然是 R01；只有状态、模型或学习算法变更时，才是新的 R 路线。

## 5. Reward 目录：A 表示训练反馈，不是官方计分

官方 score 始终由未修改的环境决定：收集金币 `+1`，炸死对手 `+5`。评估永远以官方 score 为主指标。

`A` 只影响训练中 Q-learning 的更新目标。评估时不学习，因此 reward 版本不会修改评估的官方分数。

| Reward | 事件反馈 | 研究问题 | 状态 |
|---|---|---|---|
| `A00` | `COIN_COLLECTED +1`；`KILLED_OPPONENT +5`；其余 0 | 纯官方正事件是否足够？ | 已冻结、已完成 |
| `A01` | A00；任一死亡（`KILLED_SELF` 或 `GOT_KILLED`）每次 `-5` | 明确的生存代价能否消除自杀，而不让 agent 只会等待？ | 已完成；消除自杀，但未产生 Classic 采币 |
| `A02` | A01；`CRATE_DESTROYED +0.1`；`COIN_FOUND +0.2` | 小的、通向真实金币的中间信号能否解决稀疏 credit assignment？ | 已完成；只有极弱 Classic 信号，不足以投入长训 |
| `A03` | 待单独设计 | 是否需要 potential-based 的距离/危险 shaping？ | 保留，不实现 |

### Reward 版本的约束

1. **不得修改 A00 的含义。** 已完成的 A00 result 是长期比较基线。
2. 新 reward 必须以版本号新增，例如 `A01`，而不是把全局 A00 表直接改掉。
3. 同一个连续训练 checkpoint 内 reward 必须固定。不得训练 300 局 A00 后悄悄切成 A01，因为旧 Q 值优化的目标不同。
4. `A01` 先只增加死亡惩罚；不同时增加炸箱奖励、场景混合或模型变化。
   官方自杀会同时记录 `KILLED_SELF` 与 `GOT_KILLED`，但它们只代表一次死亡，因此 A01 只扣一次 `-5`。
5. 由于 R01 的立即合法性 mask 已使 invalid actions 长期为 0，第一轮不把 `INVALID_ACTION` 惩罚作为一个需要研究的变量。
6. A02 的辅助项必须远小于真实金币 `+1`；否则 agent 可能学习“刷箱子”而非拿官方分。

`-5` 是 A01 的预注册起点：它与官方击杀 reward 同尺度，也相当于五枚金币的机会成本。它不是被假定为最优数值；只有 A01 显示正向证据后，才单独比较 `-2.5 / -5 / -10`，而不是一开始网格搜索所有组合。

## 6. 课程目录：C 表示训练任务分布

| Curriculum | 任务安排 | 要回答的问题 | 状态 |
|---|---|---|---|
| `C00` | 只训练一个固定 task | 该 task 上 reward 或路线本身能否学习？ | 已使用、也是 A01/A02 的首选比较方式 |
| `C01` | 从 A00 Coin Heaven checkpoint 继续；350 局 `T03` + 150 局 `T01`，每段 50 局 | Coin 导航能力能否在 70/30 Classic/Coin 继续训练中保留并迁移？ | 已完成、失败诊断 |
| `C02` | 能力阶梯：`T01 → T02 → T03` | 能否先学导航，再学安全炸箱，最后应对稀疏 Classic？ | 候选，需先选择有效 A 版本 |
| `C03` | rehearsal 混合：以 `T03` 为主，穿插 `T02` 与 `T01` | 能否在学习 Classic 时保留导航与安全炸箱能力？ | 候选，比例和切换粒度待预注册 |
| `C04` | `T03` 加固定对手，再扩展对手池 | 是否能把 solo 能力迁移到对抗？ | 以后才启动 |

### C01 的准确记录

C01 没有改变 R01 模型、算法、状态、mask 或 A00 reward。它只改变训练经历：从 Coin Heaven checkpoint 出发，按 50 局一个片段，完成 350 局 solo Classic 与 150 局 solo Coin Heaven。

结果显示：Classic 平均约 `0.20` coins/score 每局、`1.00` suicides 每局；Coin Heaven 保留能力从 A00 的 `29.68` 降到约 `9.23`。这说明 A00 下的 50 局粗粒度切换不是可投入长训的课程；它不证明任何未来 A01/A02 课程必然失败。

### C02/C03 的执行原则

- `T01` 教直接可见金币导航，不教炸箱；
- `T02` 提供大量隐藏金币，是“炸箱、逃生、回收”的能力练习场；
- `T03` 是最终 solo 主评估任务，奖励最稀疏；
- `C03` 的每个比例都必须是独立 config，例如 `classic=70%` 与 `classic=50%` 不能共用一个模糊的“mixed”名称；
- 场景切换粒度（例如每 10 局或每 50 局）也是课程变量，必须记入名称和 config；
- 在进入 C02/C03 前，所选 reward 版本固定，不在课程中途改变。

## 7. 推荐实验顺序

这里区分两类工作：先做可解释的**受控比较**，再做目标明确的**能力课程**。

### 阶段 0：已完成的 A00 基线

| 实验 | 结论 |
|---|---|
| `R01_A00_C00_T01`：Coin Heaven pilot | 能学直接找币；总体 `29.68 ± 7.57` coins/score 每局，但并未稳定收集全部 50 枚币，且仍有自杀。 |
| `R01_A00_C00_T03`：Classic pilot | `0.00 ± 0.00` score/coins；没有稳定采集信号。 |
| `R01_A00_C01`：70/30 Classic/Coin | Classic 的极少得分伴随几乎每局自杀；不值得直接延长。 |

### 阶段 1：A01 生存消融（已完成，负面但有信息的结果）

运行 `R01_A01_C00_T03`：

- 与既有 A00 Classic pilot 完全相同的训练 seed、预算、checkpoint 间隔和 greedy 评估；
- 只有 reward 从 A00 改成 A01；
- 无对手；
- 训练后在 `T03` 上评估官方 score、coins、suicides、steps、invalid actions 和 seed variance。

**通过条件不是单独降低 suicides。** 候选必须同时显示：自杀下降、官方 coins/score 出现稳定改善、平均 steps 合理上升而不是仅仅 `WAIT` 到超时。具体数值门槛在运行 config 前写死，不能看完结果后再修改。

Hetzner pilot `r01_a01_classic_pilot_20260825`（commit `f1bcd5c`）使用相同的 3 个训练 seed、500 局和 15 条主评估。Classic 主评估为 `0.000 ± 0.000` official score/coins、`0.000 ± 0.000` suicides、`400.0 ± 0.0` steps、`0` invalid actions；三条 training seed 的 greedy Classic 分数均为 0。也就是说，`-5` 确实让最终 greedy policy 不再自爆，但它学成了存活/等待，而不是安全采币。诊断中 Coin Heaven 仅为 `0.411 ± 0.205` coins，Loot-Crate 为 `0.000 ± 0.000`；因此 A01 没有晋升。这满足 A02 的预先设定启动条件：死亡降低但隐藏金币链路没有学习信号。

### 阶段 2：A02 稀疏奖励消融（已完成，未通过）

若 A01 已经减少自杀，但仍因没有足够炸箱信号而几乎不拿币，运行 `R01_A02_C00_T03`：

- 保持 R01、T03、种子和预算不变；
- 只从 A01 增加 `CRATE_DESTROYED` 与 `COIN_FOUND` 的小正反馈；
- 仍然用官方 Classic score 选择候选，而不是用训练 reward 选择。

Hetzner pilot `r01_a02_classic_pilot_20260825`（commit `bfd112d`）也完整运行了 3 个 training seed × 500 局，并在三个任务各完成 15 条 30-round greedy eval。Classic 主评估及 Loot-Crate 诊断都为 `0.0022 ± 0.0086` coins/score 每局（450 局评估总共约一枚币）；Coin Heaven 为 `0.4689 ± 0.2827` coins。所有 suite 都是 `0` suicides、`400.0` steps、`0` invalid actions。按 training seed 分组，Classic 只有 seed 1001 为 `0.0067 ± 0.0149`，1002/1003 都是零，因此这不是稳定改善。A02 没有晋升，也不值得直接延长到 1,500–2,000 局。

### 阶段 3：选定 reward 后才做课程训练

只有从 A01/A02 中选出能同时带来官方得分、存活与稳定性的版本，才可固定为 `A*` 后启动：

```text
R01_A*_C02 : T01 Coin Heaven → T02 Loot-Crate → T03 Classic
R01_A*_C03 : 以 T03 为主，按明确比例穿插 T02/T01
```

当前 A01/A02 都没有达到这个门槛，因此**不得把 C02/C03 当作“多跑一些就会好”的替代品**。下一项工作应先单独预注册一个最小课程设计：分别验证选定 reward 下的 `T01`（直接金币导航）与 `T02`（炸箱、逃生、收集）是否各自可学，再定义 checkpoint continuation、每段轮数和 C02 的迁移评估。初始阶段不加入对手；只有 solo Classic 已有稳定非零官方得分后，才进入 C04 的对抗任务。

## 8. 公共评估协议与报告要求

每条候选路线均使用同一份可复现协议：

- 训练 seed：`1001, 1002, 1003`；
- 默认 pilot：每 seed 500 rounds，每 50 rounds checkpoint；
- greedy eval seed：`2001–2005`；
- 每个 checkpoint / eval seed：30 rounds；
- 结果按每局归一化，并报告 15 个 eval job 的均值和标准差；
- 另外按训练 seed 分组报告，区分“训练随机性”和“评估地图随机性”。

每次汇总至少报告：

| 指标 | 含义 |
|---|---|
| official score | 主指标；金币 `+1`、击杀 `+5` 的官方总分 |
| coins / kills | 分数来源 |
| suicides | 每局自杀次数；必须与分数一起看 |
| steps | 过早死亡、正常探索或纯等待的区别 |
| invalid actions | 立即合法性 mask 是否仍正确 |
| mean ± std | 稳定性；不能只报单个最高 seed |

训练 reward 上升不能作为成功结论；只有官方 score、coins、生存与 seed variance 的联合改善，才表示 agent 真的变强。

## 9. 当前决策摘要

1. 保留 `R01_A00`，不回写、不覆盖，不把失败的 C01 长训化。
2. `R01_A01_C00_T03` 已完成：自杀归零但 Classic score/coins 仍为零，说明单独死亡惩罚不足以训练目标行为。
3. `R01_A02_C00_T03` 也已完成：弱炸箱/发现金币信号只产生约一枚/450 局 Classic eval 的极弱信号，不能作为长训或晋升依据。
4. 下一项不是直接混合任务或延长轮数；先单独写出并评审 C02 的最小能力阶梯设计（T01、T02 的单任务可学性 gate，checkpoint continuation 与迁移 eval）。
5. R02/MLP 暂停；它是未来单独的 `R` 比较，不用来掩盖 reward 或课程问题。
6. 对手训练属于后期任务，不在当前 solo 采币和安全炸箱阶段混入。
