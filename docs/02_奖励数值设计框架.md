# 奖励数值与超参数的定量设计框架

> 状态：2026-08-25 新建。
>
> 用途：**在跑实验之前**用公式算出 reward 权重、死亡惩罚、`epsilon`、`gamma`、`alpha` 该取什么值，而不是看完一次结果再改数字。
> 本文只提供推导与计算方法；具体选定的版本写在 [01_实验路线_奖励_课程训练设计.md](01_实验路线_奖励_课程训练设计.md)。

## 0. 为什么需要这套框架

A01（死亡 `-5`）与 A02（A01 + 炸箱 `+0.1` + 发现金币 `+0.2`）在 solo `classic` 上的最终 greedy 策略是**全程等待**：15 条评估共 450 局，`0.000` / `0.0022` 官方分、`0` 自杀、`400.0` steps。

这**更可能不是**"没学会"。下面的近似模型给出一个具体解释：solo 场景下"从头等到底"的价值**恰好为 0**（严格），而在 A01/A02 的奖励下"放一颗炸弹"的期望价值是显著负数（近似估计，余量远超模型误差）。若如此，Q-learning 收敛到等待就是在正确优化一个被写错的目标。这是一个有实测支持的解释，不是证明。

同一套公式还能同时解释 A00 的失败（机制完全不同：信号饥饿），以及为什么 `-2.5 / -5 / -10` 这个原定的消融网格三个点都注定给出同一个 0 分结果。

## 2. 核心模型：把"放一颗炸弹"当作一个宏动作

> ### ⚠️ 这是一个近似设计模型，不是定理
>
> 本节的公式建立在**平均轨迹统计**之上：`n_c`、`n_f`、`n_g`、`p` 都是对整个 pilot 求平均得到的标量，而真实的它们**依赖状态、位置、地图局部结构与后续策略**。因此：
>
> - 它**不能**证明某个策略是全局最优；
> - 它**不能**替代实际运行；
> - 它给出的是**数量级判断与设计起点**，用来避免在明显不可行的数值区间里浪费实验。
>
> 使用方式：把它当作跑实验前的**一致性检查**（"这个配置有没有可能产生非零得分？"），而不是结论。每次实验后都要用实测值回填 §1.3 的常数并重新核对。

把整局游戏抽象成反复在两件事之间选择：

- **零动作 `WAIT`**：永远合法，reward 恒为 0，无风险。
- **风险动作 `BOMB`**：一次"放弹 → 逃生 → 等待爆炸 → 回收"的完整尝试。

**其中有一半是严格的，另一半是近似的，必须分清：**

- **严格部分：** solo 场景下"从头等到底"这个策略的价值**恰好等于 0**。没有对手、没有别人的炸弹，一直 `WAIT` 就一定活到 400 步且一分不得。所以**存在一个价值恰好为 0 的安全策略**是事实，不是估计。因此任何策略要被选中，其期望回报必须为正——这一步是严格的。
- **近似部分：** "放炸弹这条路的期望回报是多少"只能用 pilot 的平均统计去估。下面的 `EV(bomb)` 是**单次炸弹循环的均场近似**，它忽略了状态依赖、位置依赖，也忽略了"一次成功的炸弹会改变后续局面（箱子变少、金币露出）"这种耦合。

所以正确的表述是：**"永远 WAIT"提供了一个价值为 0 的下界；当近似模型给出 `EV(bomb) < 0` 时，有充分理由预期学到的策略会退化为等待**——这是预测，不是证明。A01/A02 的实测结果与这个预测一致（greedy 在 `coin-heaven` 的 12,000 步中 WAIT 11,992 次），但一致不等于证明。

### 2.1 期望值公式

设 reward 权重为 `w_coin`（采币）、`w_crate`（炸箱）、`w_found`（露币）、`w_safe`（安全完成一次自己的炸弹）、`D`（单次死亡惩罚的**绝对值**），令

```
G = n_c · w_crate + n_f · w_found + n_g · w_coin        # 每颗弹的确定性收益
```

则

```
EV(bomb) = G + p · w_safe − (1 − p) · D                              …… (1)
```

### 2.2 可行性阈值 `p*`

令 `EV(bomb) > 0` 并对 `p` 求解：

```
        D − G
p* = ─────────── ,        EV(bomb) > 0  ⟺  p > p*                    …… (2)
      D + w_safe
```

`p*` 就是**"这套奖励要求 agent 的逃生成功率至少达到多少，放炸弹才划算"**。它是判断一个 reward 版本是否可用的第一个数。

### 2.3 逆向设计公式（这是你真正要用的那一条）

反过来：先决定"我希望 agent 在逃生成功率达到 `p_target` 时就开始愿意放炸弹"，再解出死亡惩罚：

```
       G + p_target · w_safe
D = ─────────────────────────                                        …… (3)
          1 − p_target
```

**用法示例**（代入 §1.3 的实测值 `G = 0.311`）：

| 目标 `p_target` | `w_safe = 0` | `w_safe = 0.3` |
|---:|---:|---:|
| 0.50 | `D = 0.62` | `D = 0.92` |
| **0.55** | `D = 0.69` | **`D = 1.06`** |
| 0.60 | `D = 0.78` | `D = 1.23` |
| 0.70 | `D = 1.04` | `D = 1.74` |
| 0.90 | `D = 3.11` | `D = 5.81` |

> 这就是 `D = −1` 的来源：**在 `w_safe = +0.3` 且目标存活率 55% 时，公式 (3) 直接给出 `D ≈ 1.06`。**
> 反过来，`D = −5` 对应 `p_target = 0.938`（无 `w_safe`）或 `0.885`（有 `w_safe`）——**要求 agent 在零冗余的 4 步逃生窗口里做到接近完美，这是 A01/A02 失败的全部原因。**

## 3. 探索代价：`epsilon` 对 `p` 的影响（启发式估计）

`p*` 算出来还不够，还必须问：**这个 `p` 在训练中大致可达吗？**

逃生需要连续 `L = BOMB_TIMER = 4` 步都走对。ε-greedy 每步以 `epsilon` 概率随机选一个合法动作，其中选中正确动作的概率约为 `1/|A_legal|`（典型 `|A_legal| ≈ 4`）。在**"每一步只有一个正确逃生动作、任何偏离都致命"**的简化假设下，即使 greedy 策略完全正确，一次逃生的成功率约为

```
p_ref(ε) = ( 1 − ε · (1 − 1/|A_legal|) )^L = (1 − 0.75 ε)^4                …… (4)
```

| `epsilon` | 0.30 | **0.15** | 0.10 | 0.05 | 0.02 | 0 |
|---|---:|---:|---:|---:|---:|---:|
| `p_ref` | 0.361 | **0.620** | 0.732 | 0.858 | 0.941 | 1.000 |

> ### ⚠️ `p_ref` 是参考估计，不是严格上界
>
> (4) 的三条假设都可能不成立，而且**误差方向不一致**：
>
> | 假设 | 现实 | `p` 相对 `p_ref` |
> |---|---|---|
> | 每步只有一个正确动作 | 开阔区域常有 2 个以上安全方向 | **偏高** |
> | 任何随机偏离都致命 | 很多偏离仍可在剩余步数内补救 | **偏高** |
> | `\|A_legal\| = 4` | 走廊里常只有 2–3 个 | 偏低 |
> | 逃生总是存在 | 死路 / 拐角不足时 `p = 0`，与 `epsilon` 无关 | **偏低** |
>
> 因此 (4) **不能**当作 `p` 的上界，只能当作"`epsilon` 大致会让逃生成功率损失多少"的量级参考。
> 实测 `p̂ = 0.465` 低于 `p_ref = 0.620`，与"策略不完美 + 部分死路"一致，但这只是一致，不构成验证。
>
> **这个估计唯一站得住的用法**：比较**同一个策略在不同 `epsilon` 下**的相对损失（0.15 → 0.05 大约把逃生损失从 38% 降到 14%）。用它做绝对判定（"`p*=0.689` 一定不可达"）是超出模型能力的。

## 4. 八条设计约束（跑之前逐条检查）

### M（主判据）｜可行性 + 可达性

```
p*(A)  <  p_ref(ε) − margin ,      margin ≥ 0.10                     …… (M)
```

这是设计时的**首要一致性检查**（不是硬性定理——`p*` 与 `p_ref` 都是近似量）。逐版本核对：

| 组合 | `p*` | `p_ref` | 余量 | 判定 |
|---|---:|---:|---:|---|
| A01 + ε=0.15 | 0.992 | 0.620 | −0.372 | ❌ 差距极大 |
| A02 + ε=0.15 | 0.938 | 0.620 | −0.318 | ❌ 差距极大 |
| **A03 (D=1) + ε=0.15** | **0.689** | **0.620** | **−0.069** | ⚠️ **略为不利，但在模型误差之内** |
| A03 (D=1) + ε: →0.05 | 0.689 | 0.858 | +0.169 | ✅ |
| A04 (D=1, w_safe=0.3) + ε=0.15 | 0.530 | 0.620 | +0.090 | ⚠️ 余量不足 |
| **A04 + ε: →0.05** | **0.530** | **0.858** | **+0.328** | ✅✅ |

> **这张表怎么读（以及不该怎么读）：**
>
> 1. **A01/A02 的余量是 −0.32 ~ −0.37，远超模型误差**。这个量级的差距不需要精确模型也能判断，因此"A01/A02 不值得继续长训"是可靠结论。
> 2. **A03 的余量是 −0.069，落在模型误差范围之内。**这意味着模型**无法预测** A03 的成败——它可能刚好翻正，也可能仍然为负。这正是 A03 值得跑的原因：它是模型误差最大的那个点，实测值信息量最高。
> 3. **不能说"单独改 reward 或单独改 epsilon 已被证明不够"。**只能说：**按这个近似模型，单独改动的预期余量不稳健**（A03×E00 为 −0.069，A04×E00 为 +0.090，都在 ±0.10 以内），因此把两者拆成连续的单因素实验比一次性都改更稳妥。
> 4. 因此实验按阶梯做的理由是**归因清晰**（一次一个因素），而不是"已经证明必须两者都改"。

### C1｜信号密度

```
ρ⁺ = 每局产生非零正 reward 的事件数  ≥  1                             …… (C1)
```

否则所有 `Q ≈ 0`，`argmax` 由随机初始化决定，策略退化成常数或二周期。

| 版本 | `ρ⁺`（`classic`）| 判定 |
|---|---:|---|
| A00 | **0.006** | ❌ 比下限低 160 倍 ⇒ 观察到 `RLRLRLRL…` 二周期 |
| A01 | 0.069 | ❌ |
| A02 | 4.76 | ✅（A02 已经修好了 C1，但违反 M）|
| A00 @ `coin-heaven` | 35.1 | ✅ |

> **A00 与 A01/A02 的失败机制不同**：A00 是信号饥饿（C1），A01/A02 是风险尺度错误（M）。两者都显示为"0 分"，但修法完全相反，文档必须分开记录。

### C2｜相对尺度

```
每个辅助权重 w_aux ≤ w_coin / 3 = 0.33
每颗弹的辅助总量 G_aux = n_c·w_crate + n_f·w_found + p·w_safe ≤ w_coin = 1.0   …… (C2)
```

A04 检查：`2.364×0.1 + 0.169×0.2 + 0.53×0.3 = 0.428 ≤ 1.0` ✅，且每项 ≤ 0.33 ✅。

### C3｜不可刷分（anti-hacking）

每局能放的炸弹数上限：

```
N_att = min( MAX_STEPS / T_cycle , N_crates / n_c ) = min(400/6, 123.4/2.364) = 52.2
κ = N_att · G_aux / S_official_max                                   …… (C3)
```

| 组合 | 每局辅助上限 | 官方满分 | `κ` | 判定 |
|---|---:|---:|---:|---|
| A02 @ `classic` | 14.1 | 9 | 1.57 | ⚠️ |
| A04 @ `classic` | 29.8 | 9 | **3.31** | ⚠️ 必须退火 + 监控 |
| **A04 @ `loot-crate`** | 29.8 | 50 | **0.60** | ✅ |
| A04 @ `coin-heaven` | 0 | 50 | 0 | ✅ |

> **在 `classic` 上不可能同时满足 C1 和 C3**：只有 9 枚金币却有 123 个箱子，任何足够稠密的箱子信号都必然超过官方满分。
> 这是 **T02 `loot-crate` 作为训练任务的第二个独立理由**（第一个是 5.5× 的含币率）。
> 在 `classic` 上必须接受 `κ ≈ 3`，并用两件事对冲：(a) promotion 永远只看官方分；(b) 最终阶段用 A08 把辅助权重退火到 0。

### C4｜无自杀捷径

```
若引入每步时间代价 c > 0，则必须 D ≥ c · E[剩余步数]                    …… (C4)
```

**结论：`c = 0`，明确不要加每步惩罚。**
反例：`c = −0.01/步` 时，等满 400 步 = `−4`，而立刻自杀 = `−D = −1` ⇒ **自杀反而成为最优解**。"小死亡惩罚"与"时间代价"在数学上互斥。要打破 WAIT 吸引子，正确工具是让 `EV(bomb) > 0`（约束 M），不是让 `WAIT` 变负。

### C5｜折扣可达

金币在链条末端，必须在折扣后仍有可观数值：

```
γ^{L_chain} ≥ θ ,  θ = 0.6   ⟹   γ ≥ θ^{1/L_chain}                    …… (C5)
```

`classic` 的完整链条 `L_chain ≈ 13` 步（走到箱旁 3 + 放弹 1 + 逃生 4 + 等爆 1 + 走回采币 4）：

| `γ` | 0.95 | 0.96 | **0.97** | 0.98 | 0.99 |
|---|---:|---:|---:|---:|---:|
| `γ^13` | **0.513** | 0.588 | **0.673** | 0.769 | 0.878 |

`θ = 0.6` ⟹ `γ ≥ 0.6^{1/13} = 0.9615`。**当前的 `γ = 0.95` 不满足 C5**：放弹那一刻金币只值 `+0.513`，而 5 步后的死亡值 `0.95⁵ × (−5) = −3.87`，风险收益比 **7.6 : 1**。
`γ = 0.97` 满足 C5 且不过度放大线性 TD 的方差。**不要直接跳到 0.99。**

### C6｜步长稳定

线性 TD 的单次更新把预测值拉向 TD target 的比例是 `α · ‖φ‖²`：

```
α_eff = α · E‖φ‖²  ∈  [0.03, 0.10]   ⟹   α = α_eff / E‖φ‖²           …… (C6)
```

当前 `α = 0.02`，`E‖φ‖² = 12.54` ⇒ `α_eff = 0.251`，**比推荐上限大 2.5 倍**。在无 replay、无 target network、且带 off-policy `max` 的在线 TD 里这偏激进。
`α = 0.005` ⇒ `α_eff = 0.063` ✅。

> 注：`coin-heaven` 在 `α = 0.02` 下能学到 39 分，说明这不是致命错误，只是不最优。**`α` 应作为独立的单因素消融 `{0.02, 0.005}` 跑，不要与 reward 改动捆绑。**

### C7｜样本利用

```
N_pos = 一次训练中产生正 reward 的 transition 总数
在线 one-step Q-learning 中每个样本只被使用一次
```

A02：`N_pos(coin) = 112`，对面是 84,000 个近零/负样本；每个正样本被使用**恰好一次**。这是无 replay 路线的结构性上限，**不能靠调 reward 修复**。它是 `R04`（replay + target network）的定量启动依据，不属于 A 维度。

### C8｜零动作检测（评估侧，不是 reward）

当前的指标集（`score / coins / suicides / steps / invalid`）**无法区分"打得好所以活下来"与"冻住了所以活下来"**。A01 的 `suicides 0.000 / steps 400.0` 在 summary 里读起来像进步，实际是完全坍塌。

**任何 reward 版本的评估都必须同时报告 `wait_fraction` 与 `bomb_rate`**，否则 (M) 是否被满足在结果里看不见。指标定义见 [01 文档 §9](01_实验路线_奖励_课程训练设计.md)。

## 5. 完整设计流程（照着做）

```
输入：一个 pilot 的 official_stats.json（或已有的 A02 pilot）

步骤 1  从数据算出 n_c, n_f, n_g, p̂            （§7 的复算脚本）
步骤 2  选 w_coin = 1.0（永远不动），选 w_crate, w_found, w_safe，
        逐条核对 C2（相对尺度）与 C3（不可刷分）
步骤 3  算 G = n_c·w_crate + n_f·w_found + n_g·w_coin
步骤 4  选 p_target（推荐 0.55），用公式 (3) 反解 D
步骤 5  用公式 (2) 回代验证 p*，用公式 (4) 算 p_ref(ε)，
        核对主约束 (M)：p* < p_ref(ε) − 0.10
        —— 若不满足，先降 epsilon（改 E 维度），不要继续加大辅助 reward
步骤 6  核对 C1（ρ⁺ ≥ 1）、C4（c = 0）、C5（γ）、C6（α）
步骤 7  把 p*, p_ref, κ, ρ⁺, α_eff, γ^L 六个数写进 experiment config 的注释，
        并在结果报告中与实测 p̂ 对照
```

**步骤 7 是关键**：`p*` 是设计时的预测，`p̂ = 1 − suicides/bombs` 是实测。两者对照就是这次实验最主要的科学结论，比 official score 灵敏得多。

## 6. 反例清单：这些数值组合已被证明或可证明无效

| 组合 | 违反 | 后果 |
|---|---|---|
| `D = 5`（任何辅助项配置）| M（`p* ≥ 0.885`）| 近似模型下放炸弹为负期望，预期退化为等待 |
| 原定网格 `D ∈ {2.5, 5, 10}` | M（`p*` 全部 ≥ 0.88）| **三个点都在阈值错误一侧，网格本身信息量为零** |
| `D = 0`（无死亡惩罚）+ 稠密箱子奖励 | 无风险项 | 疯狂炸箱 + 每局自杀；作为**诊断对照 A05** 有价值，不能作为主线 |
| 仅官方 reward（A00）@ `classic` | C1（`ρ⁺ = 0.006`）| `Q ≈ 0`，`argmax` 由初始化决定 ⇒ `RLRLRLRL` 二周期 |
| 每步时间代价 `c < 0` + 小 `D` | C4 | 立刻自杀成为最优解 |
| `w_safe` 无"炸到箱子"门控 | C3（`κ → ∞`）| 在空地反复安全放弹刷分 |
| `w_safe` 无"存活"门控 | 语义错误 | 退化成 `BOMB_DROPPED` 奖励，直接鼓励盲目放弹 |
| `γ = 0.95` @ `classic` | C5（`γ^13 = 0.513`）| 末端金币被折掉一半，风险收益比 7.6:1 |
| `α = 0.02` | C6（`α_eff = 0.251`）| 在线 TD 步长过大，估计噪声偏高 |

## 7. 复算方法（保证这些常数可验证）

所有常数都能从已有 artifact 重新算出，不依赖本文：

**行为常数 `n_c, n_f, n_g, p̂`** —— 训练侧从 `runs/<run>/jobs/train_seed*/agent/agent.jsonl` 的 `round_end` 记录累加 `events` 字段；评估侧直接从 `official_stats.json` 的 `by_agent` 取：

```
n_c = crates / bombs      n_g = coins / bombs
p̂  = 1 − suicides / bombs        （solo 场景下 KILLED_SELF 是唯一死因）
```

`n_f`（`COIN_FOUND`）不在官方 `EVENT_STAT_MAP` 里，只能从训练侧 `agent.jsonl` 得到；评估侧用 `coins / crates` 作为替代探针。

**地图常数** —— 复现 `environment.BombeRLeWorld.build_arena` 的逻辑（不需要 pygame），对 200 个 eval seed 统计 `arena == 1` 的数量与 `collectable=True` 的金币数。

**`E‖φ‖²`** —— 直接调用 `agent_code/research_agent/state.py:handcrafted_v1`，在采样状态上取 `(φ**2).sum(1).mean()`。

**吞吐** —— `agent.jsonl` 首末行的 `timestamp_utc` 之差。

> 建议后续把这四段复算固化为 `scripts/design_constants.py`，使每次 pilot 结束自动刷新本文的 §1.3 表格。当前是手工复算。
