## 3. 表示：`board_egocentric_v2`

`7 × 17 × 17 + 6 = 2029` 维。相对 v1 只有两处改动，**两处都是可证明的，不是假设**。

**① 删掉 v1 的 `self` 通道。** `_egocentric_crop` 以 agent 为中心裁剪，所以那一层平面
对**任何**状态都是同一个常量数组（中心一个 1）。289 个恒定输入携带零信息。
测试 `test_v1_self_plane_is_the_same_constant_for_every_state` 直接把这件事钉死。

**② 加两个全局标量：**`visible_coins`（当前地上的金币数 / 50）与
`crate_fraction`（箱子数 / 非石墙格数）。「地图快清空了、该去打人了」这件事，
17×17 窗口加 v1 那四个标量都表达不出来。两者都是**当前状态可算的**，不需要场景参数。

**一个原计划里做不成的事：`own_bomb` 通道。** 官方 `game_state` 的炸弹是
`((x, y), timer)`，**不带所有者**（`environment.py:406`）。所以「这颗弹是不是我的」
不是观测状态的函数。可以从 agent 自己的动作历史重建，但那会让 encoder 变成有状态的，
而诊断脚本 import 的正是这些函数——「agent 看到的数」和「判它的数」不能分叉是这条项目线
一直守住的性质。而且**单人训练时全部炸弹本来就是自己的**，这个通道在训练分布上恒等于
`bomb_countdown`。因此**明确不做**，理由写进代码注释。

所有通道值都落在 **1/20 网格**上（二值面是 0/1，`bomb_countdown` 步长 1/4，
`future_danger` 步长 1/5），这是 §5 能成立的前提，由测试对真实编码状态逐点断言。

## 4. 探索：为什么必须新建 `E07`

**`E00`–`E06` 全部从 ε = 0.30 起步。**这在手工特征 + 线性/小 MLP 上从来不是问题——
那种模型初始化后的 greedy 动作近乎任意，0.30 足够探索。

**随机初始化的 CNN 不同**：它的 argmax 在所有状态上近乎恒定，ε = 0.30 意味着
70% 的步在执行同一个固定动作，buffer 里灌满一条轨迹。

这不是推理，本轮的 smoke（`runs/m4_prep_smoke`，E00 ε=0.15）直接测到了：

| 未训练 CNN 的贪心评估 | 值 |
|---|---:|
| `official_wait_fraction` | **0.998** |
| `distinct_cells`（整局走过的不同格子） | **1.9** |

**它站在原地不动。**如果 anchor 用 E0x 家族起跑而学不动，会被错误归因成「CNN 不行」。

- **`E07`**：ε 从 **1.00** 保持 100 回合（buffer 填充期），再over 900 回合线性降到 0.05，其后停在 floor。
- **`E08`**：**只把起点改成 0.20**，其余完全相同——给 BC 热启动臂用，否则高 ε 会在克隆策略被用上之前就把它花掉。

两者都按**绝对回合数**计数，这带来一个 M3 线没有的性质：

> **round N 的 checkpoint，就是「预算 N 回合」那个臂的最终模型，逐位相同。**
> 所以一次 10,000 回合的 run **包含了所有更短预算的臂**，不需要单独跑预算实验。
> 测试 `test_an_absolute_schedule_makes_a_checkpoint_budget_independent` 断言了这一点。
> 这一条在 `E01`（比例定义）下不成立，正是 §0.14 / §0.18 那一串混淆的来源。

## 5. replay 的 uint8 存储

两份 float32 的 2029 维状态是 **16.2 KB/条**，100k buffer 就是 **1.6 GB／job**，
8 路并行放不下。改成 1/20 网格上的 uint8 码后是 **4.1 KB/条、406 MB／job**。

**这是内存布局，不是近似**：`_encode_board` 对偏离网格的值**报错而不是四舍五入**，
解码走查表。测试对一个真实编码状态断言 round-trip **逐位相等**。
手工特征路线（其分量是 BFS 距离和比值，本就不在任何网格上）走原来的 float32 路径，
一个字节没动，M1–M3 的历史结果仍可复现。

## 6. 最终配方

| 项 | 值 | 备注 |
|---|---|---|
| 表示 | `board_egocentric_v2`，7×17×17 + 6 = **2029** | §3 |
| 网络 | Conv(7→32) → Conv(32→64, s2) → Conv(64→64, s2) → Flatten(1600) ⊕ MLP(6→32) → FC256 → 6 头 | **477,286 参数** |
| 算法 | `double_dqn` + target network | §0.17：在 M3 上分数没变好，但自炸死亡 −34%、「有方案却仍死」−71% |

| 优化 | Adam **2.5e-4**、Huber、grad clip 10 | |

## 7. 一个被自己的实测推翻的结构假设（记录用）

设计时的论证是：「爆炸十字差一格就是生死，stride 下采样会模糊格位对齐，所以早期层必须
保持全分辨率」。听起来完全合理。**实测（batch 32→64，单线程 Apple M4）：**

| 候选 trunk | flatten | 参数 | 梯度步 (batch 64) |
|---|---:|---:|---:|
| **A 两次早 stride（原设计）** | 1600 | 477k | **32.4 ms** |
| B 三层全分辨率 + 末端 s2 | 5184 | 1.43 M | **104.3 ms** |
| C 两层全分辨率 + s2 + 一层 | 5184 | 1.40 M | 60.3 ms |
| D 三层 32 通道全分辨率 + s2 | 5184 | 1.38 M | 64.5 ms |
| E 一层全分辨率 + 两次 s2 | 1600 | 514k | 49.9 ms |

**3.2 倍的吞吐差，就是 3.2 倍的 env steps**——对一个从零学的深度 agent，那是最稀缺的资源。

而且论证本身比听起来弱：窗口是 egocentric 且尺寸固定，**stride 网格相对 agent 的偏移是固定的**，
右边一格永远落在下采样图的同一位置。这是「一致的下采样」而不是「混叠」，CNN 可以在通道维上
把两个格子分开。

**因此 anchor 采用 A。**但保留一个诚实的反向证据：**同一份示范集、同样 3 epoch 的
行为克隆，B 的验证准确率 0.911，A 是 0.897（+1.4pp）**。分辨率确实带来了一点东西，
只是要付 3 倍。**「全分辨率 trunk」因此作为预注册的单因素臂留下**，只在 anchor 出现
看起来像空间混淆的平台期时才跑。

## 8. 奖励与配方的迁移边界

判据：**这一项依赖的是环境事实，还是依赖函数近似器的误差结构？**

| 项 | 迁移性 | 处置 |
|---|---|---|
| 官方 +1 金币 / +5 击杀 | 完全 | 恒定 |
| A01–A03 事件奖励（死亡 −5、非法 −0.1、炸箱 +0.1、发现金币 +0.2） | 强 | 直接用，**不重扫**。加大死亡惩罚已被 §7.16.5 关掉 |
| **A06 势函数** | ⚠️ 尺度不迁移 | anchor 先带着跑；**A06 on/off 是预注册的单因素臂** |
| **n-step** | ⚠️ 不保证 | 取 n=3；只在需要时抽查 n=1 vs 5，不重做网格 |
| 学习率 / 优化器 | 不迁移 | 已取 CNN 侧的 2.5e-4，不沿用 M3 的 1e-3 |
| `T02` 训练 / `T03` 评估 | 强（环境层结论） | 沿用 |
| solo 训练 | 沿用 | §7.15.3/§7.19：对手训练 score 差 6.7%（噪声内），单人 classic 代价 −68% |
| 预算 | **不可从 M3 外推** | §0.18 在 M3 上测出 2000→5000 不可分辨、比赛设置反而变差；但那是一个 62 维输入的饱和 MLP。M4 靠 §4 的绝对时间表**从一次 run 里直接读出预算曲线** |

**A06 值得单独说一句**：它的 Φ 用 BFS 距离算，等于把手工线的领域知识从后门放回自动特征线。
如果 anchor 关掉 A06 也能学，那是报告里一个真结论；如果不能，也必须写明这条线依赖它。

## 9. 吞吐实测与「A100 有没有用」

`scripts/benchmark_cnn.py`，2026-08-27，Apple M4 单线程，**全部是实测值**：

| | CPU | Apple GPU (MPS) |
|---|---:|---:|
| torch import（冷进程） | 0.63 s | 0.58 s |
| `setup()` 合计 | ≈ 1.4 s | ≈ 1.5 s |
| **encode + inference p99** | **0.30 ms** | 3.05 ms |
| 对官方 0.5 s 上限的余量 | **1673×** | 164× |
| 梯度步（batch 32） | **9.59 ms** | 10.74 ms |
| **env steps / 秒**（ratio 8） | **392** | 273 |
| **300 万 env steps / seed** | **2.1 小时** | 3.1 小时 |

每个 env step 的成本拆解：**梯度步 2.40 ms（94%）+ encode/inference 0.15 ms（6%）**。

**把这个网络搬上 GPU 的收益很小，MPS 上是负的。**原因是它太小了：477k 参数、
7×17×17 输入、batch 32——单次 forward+backward 的算力需求远低于一次 kernel launch 的
调度开销，所以耗时由**每个算子的 dispatch 成本**决定，而不是 FLOPs。MPS 实测比 CPU **慢**，
就是这个机制的直接证据。

**对 A100 的判断（这是估计，不是实测——本机没有 CUDA，不要当成测量值读）：**
CUDA 的 launch 开销低于 MPS，所以 A100 大概率**比 CPU 快，但只是几倍，不是几十倍**，
而且这个倍数在 A100 和一块便宜得多的卡之间几乎没有差别——瓶颈不在显卡算力。

**结论：这个工作负载不是 GPU 形状的，横向并行才是杠杆。**

- 如果集群让你在「1×A100 + 8 核」和「32 核纯 CPU」之间选，**选 32 核**：
  20 个 job（4 臂 × 5 seed）各占一核，2.1 小时全部跑完。
- 如果 A100 节点本来就免费且核数也够，`BOMBERMAN_TORCH_DEVICE=cuda` 已经接好了，
  可以用；但**先跑一次 `scripts/benchmark_cnn.py` 实测再决定**，不要外推。
- **不需要任何新的并行化改造。**`run --jobs N` 是进程级并行，`prepare` + per-job JSON
  已经是 scheduler-agnostic 的（见 `cluster_execution.md`）。torch 默认单线程
  （`BOMBERMAN_TORCH_THREADS=1`），正是为了让 N 个 job 不互相抢核。

**一件必须先做的事：目标机器上装 torch。**M3 用的 Hetzner `.venv` 只有 numpy + tqdm，
**没有 torch**，M4 在上面一行都跑不了。内存要求：每个 job 约 **0.5 GB**（replay 406 MB
+ 模型与运行时），20 路并行约 10 GB。

## 10. 实验计划

M1–M3 那套「很多个 500 回合的单因素臂」**不迁移到这条线**：在 15 万步上比较两个 CNN 配置，
测的是初始化噪声。M4 要**少而长**。

| # | 臂 | 预算 | Gate / 读什么 | 墙钟（5 seed 并行） |
|---|---|---:|---|---:|
| **1** | **anchor** | 3M steps | **G-A**：曲线单调上升。同时从各 checkpoint 读出整条**预算曲线**（§4） | **2.1 h** |
| **2** | **+ BC 热启动**（E07→E08，两因素） | 3M | 早期 checkpoint 是否明显更高；**盯 `wait_fraction`** 与「看得见出口却 WAIT」 | 2.1 h |
| **3** | **A06 on/off** | 3M | 关掉也能学 → 报告里一个真结论 | 2.1 h |
| **4** | **dueling** | 3M | 预期效应小，排最后 | 2.2 h |
| 备 | 全分辨率 trunk / batch 64 / n=5 | 3M | 仅在 anchor 出现对应症状时 | 各 2–7 h |

**BC 臂有一个必须盯的数**：示范集 `WAIT` 出现 **0 次**（150,000 个状态，实测），
克隆出的策略从不主动等待。而 M3 的顽疾恰恰是**过度** WAIT（§0.13：117 次死亡里救命方向
清清楚楚可见却选了 WAIT）。这两件事可能互相治好，也可能变成「该等的时候不等」。
**读 `wait_fraction` 和诊断计数，不要只读 score。**

判定门槛（预注册在每个配置里）：loot-crate **4.7**；比赛设置 score **0.246** /
`coins_share` **0.022**（§0.16）。

## 11. 怎么跑

```bash
# 0. 目标机器上先装 torch，再实测一次吞吐，不要外推
python scripts/benchmark_cnn.py --rounds 10000 --steps-per-round 300

# 1. 管线 smoke（本机即可，约 5 分钟，74 个 job）
python scripts/run_experiment.py run --config experiments/m4_r07_a06_e00_smoke.json \
    --run-id m4_smoke --jobs 4 --allow-dirty

# 2. anchor（必须干净的已提交 checkout，不用 --allow-dirty）
python scripts/run_experiment.py run --config experiments/m4_r07_a06_e07_t02_anchor.json \
    --run-id m4_anchor_20260828 --jobs 8

# 3. 汇总
python scripts/aggregate_results.py --run-dir runs/m4_anchor_20260828
```

跑完照 M3 的规矩：查 `round_end_mispredictions` 的**终值**（不是逐回合求和，§0.18 更正过），
`scripts/prune_runs.py --compress-logs`，`scripts/verify_run_archives.py`。
