### 0.4 M1 收尾的结论：这个预算下种子差异是噪声，不是信号

`terminal_on_truncation` 消融（[01 文档 §7.5.8](01_实验路线_奖励_课程训练设计.md)）本身是个
小效应，但它顺带量出了一件影响后续所有实验设计的事：

> 开关只改变**因步数上限截断**的回合末步的 TD target。canonical `A03` 的 2,500 个训练回合里
> 只有 **10 个**是截断结束的，每个只改一条 transition——**约占全部约 80 万次更新的 0.001%**。
> 就这点扰动，把逐 seed 的成绩完全重排：seed 1004 从 `0.522` 掉到 `0`，
> seed 1001 从 `0.011` 跳到 `0.344`。

**因此 `5 seed × 500 局` 下的种子间差异不是「某些种子更好」，而是对微小扰动的敏感性。**

这一条把三个此前各自解释的现象统一了：E01 的效应符号在三种实现下给出 −7% / +71% / −48%；
coin-heaven 的 `34.08` 是五个 seed 里的离群点；一步学习滞后能把 A05 的存活步数从 15.6 变成 5.03。
它们是同一个放大机制的三次显现，不需要三个独立解释。

**对 M2 及以后的三条约束：**

1. **`Δscore ≈ 0.03–0.09` 量级的效应在当前预算下不可分辨。**若某个单因素实验的预期效应
   落在这个量级，先扩预算（更多 seed 或更长训练），否则结论不可复现。
2. **优先用行为指标而非 official score 做判定**（`crates_per_round`、
   `approximate_safe_bomb_rate`、`bomb_rate`、`wait_fraction`）。它们的量级变化远大于噪声。
   M2 实验 1（T02）预期的正是 `crates_per_round` 的量级变化，不受此限。
3. **任何选种产物（validation 选中的 seed / checkpoint）必须与逐 seed 分布并列报告**，
   §0.2 的规则由本节提供定量依据。

## 1. P0：terminal transition 双重更新（阻断项）

### 1.1 事实

[`runtime/experiment.py`](../agent_code/research_agent/runtime/experiment.py) 的 `end_round()` 无条件执行：

```python
self.observe(last_game_state, last_action, None, events, terminal=True)
```

而官方框架 [`environment.py`](../environment.py) 的 `do_step()` 顺序是：

```text
poll_and_run_agents()  → collect_coins / update_explosions / update_bombs / evaluate_explosions
                       → send_game_events()          ← game_events_occurred 在这里
                       → if time_to_stop(): end_round()   ← end_of_round 在这里
```

`Agent.reset_game_events()` 只在 `poll_and_run_agents()` 里调用，因此 `end_of_round` 收到的 `events` 是**同一份没有清空的列表**（额外多一个 `SURVIVED_ROUND`）。

### 1.2 两种回合结束路径不对称

`send_game_events()` 里是 `if a.train: if not a.dead: a.process_game_events(...)`，而 `a.dead` 在 `evaluate_explosions()`（更早）就已置位。因此：

| 情形 | `game_events_occurred` 收到 | `end_of_round` 收到 | 当前后果 |
|---|---|---|---|
| **存活到回合结束** | step `1..k` 全部 | step `k`（**重复**） | 同一 transition 被更新两次 |
| **死亡于 step k** | step `1..k-1` | step `k`（**全新**） | 正确，仅更新一次 |

**任何"发现重复就跳过 end_of_round"的修法都是错的**——死亡回合里 `end_of_round` 携带的是唯一一条带 `KILLED_SELF` / `GOT_KILLED` 的 transition，跳过它等于死亡惩罚 `D` 永远学不到，而 `D` 正是 §7.5 剂量-响应研究的唯一自变量。

### 1.3 证据

扫描 `runs/` 下全部 76 条 `round_end` 记录，其中 10 条为存活回合，**全部 `updates_this_round = act_steps + 1`**：

```text
segment02_coin_heaven round=2  act_steps=143 updates=144 diff=+1 coins=51 reward=51.0
segment02_coin_heaven round=4  act_steps=218 updates=219 diff=+1 coins=51 reward=51.0
segment02_coin_heaven round=7  act_steps=300 updates=301 diff=+1 coins=51 reward=51.0
```

`coin-heaven` 的 `COIN_COUNT = 50`，日志记录 **51**。最后一枚金币被计入两次。

### 1.4 修复规范

暂存一条 transition，延迟一步提交；`end_of_round` 用 `(round, step)` 判别是"重复"还是"全新"。

```python
# 伪代码。pending 保存 (old, action, new, events, key=(round, old["step"]))

def game_events_occurred(old, action, new, events):
    _commit_pending(terminal=False)          # 提交上一条：有 next_state，正常 bootstrap
    _stash(old, action, new, events)

def end_of_round(last, last_action, events):
    key = (last["round"], last["step"])
    if pending is not None and pending.key == key:
        # 存活结束：pending 就是这一条，从未提交过 → 提交且仅提交一次
        # events 用 end_of_round 的版本（是 pending.events 的超集，多 SURVIVED_ROUND）
        _commit(pending, events=events, terminal=terminal_on_truncation)
    else:
        # 死亡结束：pending 是 T_{k-1}，last 是从未送达的 T_k
        _commit_pending(terminal=False)
        _commit((last, last_action, None, events), terminal=True)
    pending = None
```

边界情形：

- agent 在 step 1 死亡 → `pending is None`，走 else 分支，正确；
- 存活分支里 `pending.new` 存在，因此 bootstrap 可行；
- 该结构与后续 n-step 所需的 transition 缓冲区同构，可直接扩展为长度 `n` 的 deque。

### 1.5 `terminal_on_truncation`：一个必须显式化、不能默认埋进代码的选择

`time_to_stop()`（[`environment.py:283`](../environment.py)）里存活结束有两种成因：

| 成因 | 语义 | 正确的 TD target |
|---|---|---|
| `step >= MAX_STEPS` | **时间上限截断**。世界没结束、agent 没死，MDP 本应继续 | **bootstrap**（Pardo et al. 2018, *Time Limits in RL*） |
| 只剩一个 agent 且无箱子、无可捡金币、无炸弹 | 未来真实回报确为 0 | bootstrap 与 terminal 近似等价 |

因此**默认 `terminal_on_truncation = false`**（即存活结束按截断处理、bootstrap），死亡结束仍是真终止（`target = r`）。

这一点对既有结论有直接影响：A01/A02 的坍塌形态是"全程 WAIT、恒 400 步"，**每一局都以截断收场**，当前代码给每局最后一步都压了一次 `target = r = 0` 的 terminal 更新，系统性地把"活到最后"的状态价值往 0 拉。修 P0 时若顺手把截断也当 terminal，等于把这个混淆项固化。

把它做成配置项，它本身就可以在有余力时当一次单因素消融。

> **消融已完成（2026-08-26，[01 文档 §7.5.8](01_实验路线_奖励_课程训练设计.md)）。**
> 均值效应小（score `0.140 → 0.169`，在 `±0.22` 内），预注册判定通过，**保持默认 `false`**——
> 依据仍是本节的语义论证，因为实测在 `5 seed × 500 局` 下分辨不出两者。
> 但该消融给出了一个更重要的副产物：开关只触及 2,500 局中 10 局的各一条 transition
> （约占全部更新的 0.001%），却把逐 seed 的成绩完全重排。见 §0.4。

### 1.9 更正（2026-08-26）：修复顺带引入了一步学习滞后

§1.2 的表格说死亡回合「正确，仅更新一次」。这对**更新次数**成立，但它被默认推出了
「死亡回合不受修复影响」——**这一步推论是错的**，复跑数据给出了反例。

**反例。**`A05` 训练中「存活到回合结束」的回合数是 **0/2500**，双重更新在原理上碰不到它，
它却是变化最大的臂（`steps` 15.6 → 5.03，且修复后 std 只有 0.06，近乎确定性）。
逐局比对 `train_seed1001` 的 `agent.jsonl`：前 3 局完全一致，**第 4 局起分歧**。

**原因。**[`environment.py:158`](../environment.py) 的 `do_step()` 顺序是：

```text
do_step(t):  poll_and_run_agents()   ← act(s_t) 在这里
             ...
             send_game_events()      ← 投递 (s_t, a_t, s_{t+1}) 在这里
```

| | transition t 何时被学习 | `act(s_{t+1})` 用的权重 |
|---|---|---|
| 修复前 | do_step t 的 `send_game_events()` | **含** transition t |
| 修复后 | do_step t+1 的 `send_game_events()` | **不含** transition t |

`act(s_{t+1})` 发生在 `poll_and_run_agents()` 里，**先于**同一 `do_step` 的
`send_game_events()`。所以延迟一步提交 = 动作选择比学习滞后一步。
**该滞后每个回合都存在，与是否存活无关。**

**三点后果：**

1. 「修复后」这批测量的是 `014cbcf` 的**合并效应**——去重 + 截断改 bootstrap +
   一步学习滞后——三者**未拆分**。§0.2 的所有判定都应按合并效应理解。
2. 在默认 `terminal_on_truncation = false` 下，延迟提交对**取正确 TD target 并非必需**：
   存活末步的正确 target 恰好就是 bootstrap，也就是立即提交时已经算对的那个。
   延迟只在 `terminal_on_truncation = true` 时才是必需的。
3. §1.4 选择延迟结构仍有一个正当理由——它同构于 n-step 所需的缓冲区，可直接扩展为长度 `n`
   的 deque。**但代价（一步滞后）此前没有被记录，现在记录在此。**

### 1.10 决定（2026-08-26）：去掉延迟结构，换成「立即提交 + 去重」

§1.9 的滞后不作为消融保留，而是**直接消除**。延迟结构是为了处理一个边界情况而改动了整条
流水线；正常的 online Q-learning 应该是：

```text
观察 s_t → 选 a_t → 环境给出 r_t, s_{t+1} → 立刻更新 Q(s_t, a_t) → 用更新后的 Q 选 a_{t+1}
```

**关键观察：默认配置下存活末步根本不需要特殊处理。**`terminal_on_truncation = false` 时它的
正确 target 就是 bootstrap，也就是立即提交时已经算对的那个。`end_of_round` 只需认出
「这一步我学过了」并跳过。

```python
def round_end_reason(new):
    # 与 environment.time_to_stop 同序：先查任务完成，再查步数上限
    if new is None:
        return ROUND_CONTINUES
    if (not new["others"] and not (new["field"] == 1).any()
            and not new["coins"] and not new["bombs"] and not new["explosion_map"].any()):
        return TASK_COMPLETE
    if int(new["step"]) >= MAX_STEPS:
        return TRUNCATION
    return ROUND_CONTINUES

def observe(self, old, action, new, events):        # game_events_occurred
    self._commit(EncodedTransition(...), terminal=self._is_terminal(round_end_reason(new)))
    self._delivered_key = (int(old["round"]), int(old["step"]))
    self._predicted_round_end = round_end_reason(new) is not ROUND_CONTINUES

def _is_terminal(self, reason):
    if reason == TASK_COMPLETE:
        return True                                  # 真终止，与开关无关
    if reason == TRUNCATION:
        return self.config.terminal_on_truncation    # 默认 False ⇒ bootstrap
    return False

def end_round(self, last, last_action, events):     # end_of_round
    if (int(last["round"]), int(last["step"])) == self._delivered_key:
        # 存活末步：observe 已按其结束原因学过恰好一次
        pass
    else:
        # 死亡末步：从未投递过，唯一带 KILLED_SELF / GOT_KILLED 的 transition
        self._commit(EncodedTransition(..., next_state=None), terminal=True)
```

框架内 `old` 与 `new` 的 `step` **是同一个值**（`do_step` 存下 `last_game_state` 后取后继状态，
其间 `self.step` 未变），而 `time_to_stop` 比较的正是这同一个计数器——这是能从 `new`
读出终止性的前提。保留的状态从「一整条 transition」缩成**一个 `(round, step)` 二元组**。

**两个让方案成立的事实（已核实）：**

1. **`SURVIVED_ROUND` 在 A00–A06 中权重均为 0**（`REWARD_TABLES` 只含 `COIN_COLLECTED` /
   `KILLED_OPPONENT` / `CRATE_DESTROYED` / `COIN_FOUND`，外加 `DEATH_PENALTIES`）。
   因此 §1.4 所说「`end_of_round` 的 events 是超集、必须用它替换」在**奖励上是零差异**，
   丢弃该超集没有代价。若将来新增一个给 `SURVIVED_ROUND` 赋权的 reward 版本，此前提失效，
   届时必须重新论证。
2. **`terminal_on_truncation` 无需延迟即可实现，但两种存活结束必须分开。**
   §1.5 把「存活结束」当成一件事、共用一个开关，这是不对的。`time_to_stop()` 的两条存活路径
   语义不同，且**先检查任务完成、后检查步数上限**：

   | 结束原因 | 判据（agent 视角） | 正确 target |
   |---|---|---|
   | **任务完成** | 无对手、无箱子、无可捡金币、无炸弹、无危险爆炸 | **`target = r`（真终止，与开关无关）** |
   | **时间截断** | `new["step"] >= MAX_STEPS` | bootstrap，除非 `terminal_on_truncation` |

   任务完成时剩余真实回报确为 0，直接注入 0 比让不准的 Q 去 bootstrap 更对；
   §1.5 原文的「近似等价」不足以作为共用开关的理由。**这一条尤其影响 coin-heaven
   被完整清空的回合。**两个判据都能从投递过来的 `new` 状态当场算出，因此仍不需要延迟。

   **一个必须测量而非假设的近似。**`time_to_stop` 的任务完成条件里有 `len(self.explosions) == 0`，
   而 explosion 在危险阶段之后还会以**烟雾**形态存在 2 步，`explosion_map` 只暴露危险阶段。
   因此上表的判据是**必要条件**，最多可能提前 2 步触发。运行时**逐条比对自己的预测与框架的
   实际行为**，把分歧计入 `round_end` 的 `round_end_mispredictions`：

   - 预测「本步结束」却又收到下一步投递 → 假阳性；
   - 未预测结束却收到 `end_of_round` 的重发 → 假阴性。

   实测：A05 哨兵 2,500 局训练中 `round_end_mispredictions = 0`。

**不变量（与 §1.6 的验收条件逐条对应，全部保持）：**

| 不变量 | 如何保证 |
|---|---|
| 每条 transition 恰好一次更新 | 存活末步靠 key 相等去重；死亡末步靠 key 不等识别 |
| 死亡惩罚恰好计一次 | 死亡末步是唯一携带 `KILLED_SELF` / `GOT_KILLED` 的 transition |
| `updates_this_round == act_steps` | 存活：k 次投递 + 跳过；死亡：k−1 次投递 + 1 次终止 |
| **动作选择无滞后（新增）** | 第 t 步提交完成后才轮到第 t+1 步的 `act` |

最后一条需要一个**新增测试**：断言第 t+1 步的动作是在包含 transition t 的权重下选出的。

**与 n-step 的关系：**`NStepAssembler` 不受影响，它已经写对了——`push` 一满 `n` 条就发射，
`n = 1` 时当场发射、零滞后。要移除的只是它下面那层 `PendingTransition`。

## 2. P1：curriculum × E01 会静默关闭 epsilon 衰减

## 4. A06：势函数塑形规范（已实现）

### 4.1 形式与保证

$$\hat r_{t+1}=r_{t+1}+\underbrace{\gamma\Phi(s_{t+1})-\Phi(s_t)}_{F(s_t,s_{t+1})}$$

按折扣求和望远镜化：

$$\sum_{t=0}^{T-1}\gamma^tF(s_t,s_{t+1})=\gamma^T\Phi(s_T)-\Phi(s_0)$$

令 $\Phi(\text{终止})=0$，整条轨迹的塑形贡献恒为 $-\Phi(s_0)$——**只与起点有关、与策略无关的常数**，故最优策略不变（Ng, Harada & Russell 1999）。

**精确表述**：$F$ 依赖 transition $(s,s')$；策略不变性成立**当且仅当** $F$ 能写成某个**只读状态的** $\Phi$ 的 $\gamma$-折扣差分。不是"不依赖 transition"。

**刷分的边界（诚实版本）**：来回横跳单次净收益为正（$\gamma=0.95$、$\Phi=-0.05d$ 时约 $+0.049$/来回），但**整条 episode 的塑形总和有界**，与横跳次数无关；而横跳会把所有真实奖励往后推、被 $\gamma^{\Delta t}$ 打掉。对比朴素塑形每个来回**净赚固定值、无上限**——这才是本质差别。

### 4.2 三条不可违反的实现约束

1. `Φ` 只读 `game_state`，**不得读 action、events 或历史**；
2. `Φ(终止) = 0`；
3. `Φ` 使用**与 learner 完全相同的 `γ`**（当前 `0.95`），且**有界**（BFS 距离必须 clip，否则 $\gamma<1$ 时有残余漂移）。

### 4.3 建议的 Φ

```python
def potential(game_state) -> float:
    if game_state is None:              # 终止
        return 0.0
    d = bfs_distance_to_nearest(reachable_targets(game_state))
    phi  = -0.05 * min(d, 20)                                    # 采集势
    phi += -0.30 if in_future_blast(game_state) else 0.0         # 危险势
    return phi
```

`reachable_targets` 的定义：

- 有可捡金币 → 金币格本身（金币格可通行）；
- 无可捡金币 → **可达且邻接箱子的合法站位**，不是箱子格本身（`field == 1` 不可通行，BFS 距离无定义）。直接复用 [`state.py`](../agent_code/research_agent/state.py) 已有的 `_crate_adjacent_cells()`。

**危险势是这一项的主要价值**：它在**状态层面**表达"我在不在未来爆炸范围内"，天然绕开 [01 文档 §7](01_实验路线_奖励_课程训练设计.md) 诊断出的 `CRATE_DESTROYED` 无法区分安全/自杀的结构性缺陷（`update_bombs` 早于 `evaluate_explosions`，自杀那步的 events 同时含两者）。因此 **A06 的优先级高于 A04 的事件级存活门控**：A04 仍在事件层打补丁，A06 在状态层一次解决且自带理论保证。

### 4.3b 实现与测试

`agent_code/research_agent/shaping.py`。三条约束各有一条测试（`tests/test_shaping.py`，10 项）：

| 约束 | 测试 |
|---|---|
| `Φ` 只读 state | 同一 state 不同 step/历史给出同一 `Φ` |
| `Φ(终止) = 0` | 直接断言 |
| 与 learner 同 `γ`、有界 | `build_shaping` 取 `config.discount`；41×41 棋盘上距离仍被 clip 到 `distance_cap` |
| 望远镜化 | `Σ γ^t F = γ^T Φ(s_T) − Φ(s_0)`，逐项数值验证 |
| 刷分有界 | 1／10／100 次来回横跳的塑形总和都 `< −Φ(s_0)` |

`round_end` 里 `official_reward` **不含**塑形项，塑形单独记到 `shaping_reward`——否则 A03 与 A06 的奖励曲线不再可比。

### 4.4 预注册

```text
对照：R01_A03_E01_C00_T02  n=1
处理：R01_A06_E01_C00_T02  n=1     ← 唯一变量：加入 Φ
```

**反证条件**：若 `wait_fraction` 上升且 `bomb_rate` 下降，说明危险势权重 `-0.30` 过大、复制了 A02 的瘫痪形态，应先降权重而非加新项。

### 8.3 关键实现决定

- **n-step 放在 runtime，不放在 learner。** `NStepAssembler` 是 §1.4 那个 pending 结构的直接推广。每条 push 进去的 1-step transition 恰好作为一条 n-step transition 的头被 emit 一次，因此 `updates_this_round == act_steps` 这个 P0 回归断言在 n>1 下继续成立（六个 smoke 全部验证）。截断收尾 flush 出更短的 bootstrapped 窗口，死亡收尾 drain 出全部后缀且都是 terminal。
- **奖励计账按游戏步，更新计账按 learner 调用。** `official_reward` 与事件计数在 push 时累加（不含塑形），`updates` 与 `td_error` 在 emit 时累加。否则 A06／n-step 的奖励曲线与 A03／n=1 不再可比。
- **egocentric 表示。** 8 通道 × 17×17 窗口 + 4 个全局标量，展平成 2316 维——`Transition.state` 对所有路线保持单一向量，只有 CNN 模型知道怎么 reshape。棋盘外用**石墙**填充，不是 0：padding 格必须和墙一样不可通行，否则网络会看见不存在的逃生路线。
- **D4 增强只对 egocentric 合法。** 手工特征向量转 90° 不是棋盘对称（方向特征会和动作标签对不上），`validate_config` 直接拒绝。棋盘变换与动作置换从同一个坐标映射派生，并有测试逐个方向核对二者一致。
- **评估 job 不分配 replay。** 贪心 rollout 从不收到 transition，M4 的 buffer 一个 job 就是几百 MB，乘上 checkpoint × seed 的评估扫描不可接受。
- **模型构造搬到 `setup()`。** 官方对 `act` 有 0.5 s 上限但不计时 `setup`。CNN 首次 `act` 原本 **3053 ms**（torch import + 建网 + 首次前向），必然超时；`runtime.warm_up()` 之后首步 **5.7 ms**、稳态 **0.44 ms**。分项实测见 §8.5。
- **torch 单线程。** 并行是跨进程的，`BOMBERMAN_TORCH_THREADS` 默认 1，避免 8 路 job 互相抢核。

### 8.5 M4 吞吐实测（2026-08-26，Apple M4，单线程）

`scripts/benchmark_cnn.py`。§5.4 要求先测再外推，所以这里全是实测值，没有一个是推算的。

| 项目 | R07 anchor | R08 dueling | 说明 |
|---|---:|---:|---|
| torch import（冷进程） | 0.71 s | — | 进程级，一个 job 付一次 |
| 首个模型构造 + 首次前向 | 0.92 s | 0.94 s | 也是进程级（torch 惰性初始化 kernel）；一个 job 只建一个模型 |
| **`setup()` 合计** | **≈ 1.7 s** | **≈ 1.7 s** | 官方不计时 `setup` |
| encode + inference p99 | **0.19 ms** | **0.21 ms** | 这才是 0.5 s 预算里花掉的 |
| **对官方上限的余量** | **2594×** | **2753×** | |
| 一次梯度步（batch 32） | 9.6 ms | 9.7 ms | `train_every=1`，每个环境步一次 |
| 梯度步吞吐 | 104 /s | 103 /s | |
| **500 局 × 312 步训练 job** | **25.4 min** | **25.7 min** | 单 seed、单线程 |

两个结论：

1. **推理不是问题。** 2500 倍余量，即使 8 路并行争 CPU 也不接近上限。
2. **M4 在预算内。** 5 个 seed 并行约 **26 分钟**一次训练 run，和 §5.1 的向量路线同一量级——因为瓶颈是梯度步而不是游戏本身。§5.2 阶段 8 给 M4 的 8–10 天不受算力约束，风险在调参不在吞吐。

一个计量陷阱：`setup` 的 0.92 s 只有**进程里第一个**建的模型会付，因为 torch 的 kernel 初始化是进程级的。把 R07、R08 反过来测，0.92 s 就跟着换到 R08 头上。benchmark 因此显式标注 `first_in_process`，不让这个数被当成路线差异。

### 8.6 BC 热启动（M4 阶梯的一节）

两条命令，都记录 SHA-256：

```bash
python scripts/collect_demonstrations.py --scenario loot-crate --seeds 9001 9002 9003 --max-states 20000
python scripts/pretrain_behaviour_cloning.py --route R07 --demonstrations pretraining/demonstrations/rule_based_agent_loot-crate_20000.npz
```

- **采集不改框架。** 直接驱动 `BombeRLeWorld`：`do_step()` 之后框架已经把它给 agent 看过的 state 和 agent 返回的 action 存在 agent 上了，直接读出来即可，不用解析 replay，也不用给 `rule_based_agent` 打补丁。`last_action` 不在六个动作里（首步之前的 `None`、被静默的异常 `"ERROR"`）的步会跳过——那是框架的替代值，不是示范者的决策。
- **拟合的是 policy，不是 value。** 用交叉熵把 Q head 当 logits 训，拟合的是 `argmax`。这么做**校准不了数值尺度**：交叉熵会把 logits 无限推开，克隆完的 Q 值比任何真实回报都大一个量级。
- **所以要重新缩放 head。** 乘一个**正**因子是 Q 函数的精确缩放，`argmax` 不变（dueling 的 V 和 A 一起缩放同样成立），于是克隆到的策略原样保留，而头几步 TD 更新不必先花力气把尺度压回来。脚本会在缩放前后比对贪心动作，不一致就报错——这个性质如果悄悄失效，等于把刚付钱买来的克隆结果扔了。
- **示范集与权重都进版本库。** 压缩后分别是 0.8 MB 和 1.9 MB。重新生成会得到不同的 digest，所以提交它们是让 `initial_model` 的 SHA-256 校验对一个新 clone 仍然成立的唯一办法。
- **一个必须记进报告的偏差**：`rule_based_agent` 在 `loot-crate` 上 `WAIT` 出现 **0** 次。克隆出的策略因此从不主动等待，等待只能靠 DQN 自己重新发现。这正是 BC 必须作为**单项**增量、和 anchor 对照着跑的原因。
